# Changelog

All notable changes to Featly will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Until version `1.0.0`, the public API is unstable and minor versions may introduce breaking changes. Breaking changes will be called out explicitly in the notes for each release.

## [0.2.0-preview.1] - 2026-08-18

The storage-provider release. Four new storage packages — **PostgreSQL, SQL Server, MySQL/MariaDB, and MongoDB** — join SQLite behind the same `IFeatlyStore` contract, each a one-line `AddFeatly<Provider>Store()` swap, with real cross-replica change push on Postgres (`LISTEN`/`NOTIFY`) and MongoDB (Change Streams). Around them: scheduled releases, flag prerequisites, a tamper-evident audit hash chain, a webhook circuit breaker, offline SDK resilience, RFC 7807 errors, `Accept-Version` negotiation, opt-in rate limiting, a CSRF layer, API-key expiry/rotation, statistical significance for experiments, and a large **security-hardening pass** (SSRF guard on webhook targets, always-on login throttle, strict CSP, environment-scoped RBAC actually enforced, ReadOnly freeze closed on every path). CI gained SonarCloud + CodeQL gates and a Playwright dashboard smoke. 881 test methods across 11 projects.

**Breaking (pre-1.0):**

- **API error shape.** Every error is now RFC 7807 `application/problem+json` (`title`/`status`/`detail`, and an `errors` map for validation) instead of the ad-hoc `{ "error": "..." }` envelope (ADR-0031, #248). Consumers that parsed `error` must read `detail`; the CLI and dashboard already do.
- **Export/import permissions.** `GET /api/admin/export` and `POST /api/admin/import` require the new `BackupExport` / `BackupImport` permissions instead of `FlagRead`/`FlagCreate` — held by the system Admin role by default; grant them to a custom role for backup tooling (#148).
- **Webhook secret is write-only.** `GET /api/admin/webhooks[/{id}]` return metadata plus a `hasSecret` flag; the HMAC secret is echoed exactly once at creation (#196).
- **Cookie sessions minted before this release fail closed** (the CSRF token claim is missing) — sign in again (#151).
- **`Accept-Version` pinning.** An unsupported major pin now returns `406` (#251). Unpinned requests are unaffected.

### Added

- **PostgreSQL storage provider — `Featly.Storage.Postgres`** (ADR-0026; #164–#178, #256, #259, #260, #272; closes #157, #179). Own internal `FeatlyDbContext` (Npgsql; native `timestamptz`/`jsonb`), every `IFeatlyStore` sub-store, `AddFeatlyPostgresStore()` (fails fast on a missing connection string; `AutoMigrate` on by default — turn it off with several replicas), `PostgresMigrationRunner`, and `featly db --provider postgres`. **Real cross-replica push:** `PostgresChangeNotifier` publishes via `pg_notify()` and a `LISTEN` hosted service delivers to every replica's SSE clients — the originating replica hears its own change back through the same path, so there is one symmetric fan-out and nothing to deduplicate. Reconnects with exponential backoff. `samples/Centralized.Postgres.Sample`: two replicas + Postgres + nginx via `docker compose up`, schema applied once by a one-shot `migrate` service.
- **SQL Server storage provider — `Featly.Storage.SqlServer`** (ADR-0032; #280–#287; closes #274). Same shape as Postgres (owned JSON collections in `nvarchar(max)`, `AddFeatlySqlServerStore()`, `SqlServerMigrationRunner`, `featly db --provider sqlserver`). Polling-only `IChangeNotifier` by design (Service Broker was judged disproportionately heavy for a push-latency-only win). **Requires `InvariantGlobalization=false`** — `Microsoft.Data.SqlClient` needs ICU; the provider, its tests, and `Featly.Cli` set it, and any host referencing the provider must too.
- **MySQL / MariaDB storage provider — `Featly.Storage.MySql`** (ADR-0033; #288–#294; closes #276). Pomelo EF Core provider, `AddFeatlyMySqlStore()`, `MySqlMigrationRunner`. Polling-only notifier. Two documented, worked-around findings: Pomelo's latest release targets EF Core 9, so this one provider pins its EF Core packages to `9.0.x` via `VersionOverride`; and Pomelo lacks `OwnsMany(...).ToJson()`, so `List<T>` properties are JSON-column scalars (`JsonCollectionConversion`), with `ListForMemberAsync` filtering in memory. **`featly db --provider mysql` is not available** — the same EF Core version conflict cannot be satisfied inside the single `featly` executable alongside the EF Core 10 providers; migrate via `MySqlMigrationRunner` directly until Pomelo ships an EF Core 10 build.
- **MongoDB storage provider — `Featly.Storage.MongoDB`** (ADR-0034; #295–#303; closes #277). The official `MongoDB.Driver` directly, no EF Core: `BsonClassMap` registration per entity (domain types stay free of `MongoDB.Bson` attributes), a custom `JsonElementSerializer` mapping `JsonElement` to native BSON, one collection per entity, and `MongoMigrationRunner` walking an ordered list of idempotent index/collection steps recorded in `__migrations`. `AddFeatlyMongoStore()`, `featly db --provider mongodb`. **Requires a replica set** (a single-node one is fine for dev; the sample runs `rs.initiate()` on first boot). **Real cross-replica push** via a Change Stream on a capped `changeNotifications` collection — MongoDB is the second provider, after Postgres, with instant push. `samples/Centralized.MongoDB.Sample`. Two things worth knowing: **`featly db rollback` is not supported** (index steps have no framework-derived "down"; use `drop` or restore a backup), and BSON's `Date` is millisecond-precision, so `AuditEntry.At` is truncated to milliseconds before the audit hash is computed (otherwise every chain would appear tampered on verify).
- **Scheduled releases** (ADR-0028; #167, #169, #170, #174; closes #159). `PendingChange.ScheduledApplyAt`: an `Approved` change with a due schedule is applied automatically by `ScheduledApplyWorker` through the exact same apply + staleness path manual Apply uses — a change that went stale since approval is skipped (`change.schedule_skipped_stale`), never forced. `PATCH /api/admin/changes/{id}/schedule` sets/reschedules/cancels (`ChangeApply` permission); the dashboard Decision panel gets a datetime picker and the Inbox an "Approved — awaiting apply" group. New `change.scheduled` event.
- **Flag prerequisites** (ADR-0027; #165, #168, #171, #172; closes #158). `Flag.Prerequisites`: a flag can require other flags in the same environment to resolve to specific variants; the engine evaluates them locally with cycle detection at write time and a `PrerequisiteFailed` reason at eval time; the SDK and OpenFeature provider surface it; the dashboard editor gets a prerequisites picker and a Met / Not met badge.
- **Tamper-evident audit log** (ADR-0030; #247; closes #208). `AuditEntry` gains `Sequence`, `PreviousHash`, `Hash` (SHA-256 over content + previous hash); appends chain under a process-wide gate; `IAuditStore.VerifyChainAsync` walks the chain and reports the first break (modified, deleted, or reordered), exempting the oldest surviving link so retention pruning stays valid. Exposed as an admin verify endpoint.
- **Webhook circuit breaker** (ADR-0029; #246; closes #207). Per-endpoint `ConsecutiveFailures` + `CircuitOpenUntil`: past the threshold, an endpoint's due deliveries are short-circuited for a cooldown (no POST, no attempt-budget spend), then one half-open probe. `CircuitBreakerThreshold`/`CircuitBreakerCooldown` on `WebhookOptions`, DB-overridable; a non-positive threshold disables it.
- **Multi-instance-safe background workers** (#242, #243; closes #237). `IPendingChangeStore.TryClaimStatusAsync` and `IWebhookDeliveryStore.TryClaimDueAsync` are single atomic conditional updates, so several server instances draining a shared database apply each scheduled change and deliver each webhook exactly once. The former "single-instance workers" limitation is resolved.
- **SDK offline resilience** (#241; closes #238). `FeatlySdkOptions.OfflineCachePath` persists each fresh snapshot to disk and re-seeds the cache before the first fetch after a restart; `BootstrapFilePath` seeds a cold start from a static JSON file (air-gapped / serverless). Both off unless a path is set; reads fail soft.
- **`Accept-Version` negotiation** (#251; closes #227). A filter at the `/api` group root honours a major pin (`1`, `1.4`, `v1`), echoes `Featly-Version` on every response, and refuses an unsupported pin with `406` + ProblemDetails; `Deprecation`/`Sunset` headers are wired for future majors.
- **Per-environment `ConfigVersion` counter** (#245, #252; closes #228). The SDK config ETag is derived from an atomically-bumped counter on the environment row instead of four `max(UpdatedAt)` queries per poll — zero extra queries on the hottest read path. `SnapshotChange.AnnounceAsync` bumps and notifies in one call so no write path can forget; auditing them fixed a latent bug where `POST /api/admin/import` never notified SSE clients.
- **Opt-in request rate limiting** (#150, #232). `Featly:RateLimiting` (DB-overridable): sliding one-minute windows partitioned per surface (`/api/auth/*`, `/api/admin/*`, `/api/sdk/*`) and per client; `429` + `Retry-After`. Off by default — **except the auth surface, which is always throttled** (see Security).
- **Synchronizer-token CSRF layer for the dashboard session** (#151). A per-session anti-forgery token is stored as a claim in the `HttpOnly` cookie and required in `X-Featly-Csrf` on every cookie-authenticated mutation (constant-time compare); Bearer requests are exempt.
- **API-key expiry + rotation** (#146, #152). Optional `ApiKey.ExpiresAt` (enforced on every request and on dashboard login), `POST /api/admin/apikeys/{id}/rotate` (mints a replacement carrying name/scope/environment/user binding, revokes the old one, returns the new token once), `featly apikey generate --expires-in` / `featly apikey rotate`, and an `apikey.rotated` event.
- **Statistical significance for experiment analytics** (#153). Per-metric two-proportion z-test against a baseline variant with a per-metric winner (fixed-horizon; sequential analysis remains deferred).
- **SDK activity** (#154) — `GET /api/admin/environments/{key}/sdk-activity`: connected SSE clients and last exposure per flag. **Stale-flag report** (#155) — `GET /api/admin/flags/stale?staleDays=`. **`featly flags list|enable|disable`** (#156).
- **DB-overridable settings** (#97–#100, #124–#126; closes #101). `SystemSetting` store + `IFeatlySettingsProvider` implementing the three-layer precedence (default → `appsettings` → database) with a Settings screen: webhook delivery, authorization auto-provision mode, audit-log retention + trimmer, approval defaults.
- **Modular feature areas via DI toggles** (ADR-0024; #120, #122; closes #112) — disabled areas disappear from the API and the UI.
- **Dashboard:** create flows for flags/configs/segments (#110, #111), a syntax-highlighted multiline JSON editor (#118, #123), an ESLint `no-unsanitized` XSS gate on every `innerHTML` sink running in CI (#313), duplicate-selector and nested-ternary sweeps (#314, #315).
- **Docs & tooling:** an image-rich documentation site on Astro Starlight (#129), refreshed screenshots (#127), `docs/RELEASING.md` (#316), a CI-gate patterns write-up (#234), CODE_OF_CONDUCT (#130), migration to `System.CommandLine` 2.0 GA (#128), FluentAssertions → AwesomeAssertions (ADR-0021, #95).
- **CI:** SonarCloud analysis with an 80 % new-code coverage / 3 % duplication quality gate (#180, #181; closes #160), CodeQL, a Playwright dashboard smoke over every routed screen, and dedicated real-database jobs for each provider.

### Security

- **SSRF guard on webhook targets** (#198; closes #189). `WebhookTargetGuard` blocks loopback, RFC 1918, CGNAT, link-local (cloud metadata), and IPv6 unique-local — as a literal check at create/update and a DNS-resolving check at delivery (defeating rebinding). Blocked deliveries dead-letter with a reason. Opt out with `Featly:Webhooks:AllowPrivateNetworkTargets`.
- **Login is always throttled** (#199; closes #190). `POST /api/auth/*` is rate-limited at `AuthPermitsPerMinute` (default 10/min per client) regardless of the master switch — the Argon2id verify was a brute-force / CPU-DoS amplifier with no throttle in the default configuration.
- **Environment-scoped RBAC actually enforced** (#201; closes #193). `PermissionFilter` now resolves the request's environment and passes it to the checker; previously it always passed `null`, so per-environment role assignments never matched.
- **API-key environment scope enforced on SDK endpoints** (#195; closes #188). A key bound to one environment gets `403` for any other; when `?env=` is omitted it resolves to its own environment.
- **Strict CSP + security headers on the dashboard** (#216; closes #202). `Content-Security-Policy` (`default-src 'self'; frame-ancestors 'none'; script-src 'self'; …`), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`.
- **ReadOnly freeze closed on every path** (#217; closes #203). Change apply/bypass/schedule and `POST /admin/import` now honour `Environment.ReadOnly` (`403`), checked before status checks so the freeze always wins.
- **DoS bounds** (#218, #219; closes #204–#206). `POST /api/sdk/events` rejects batches over `MaxEventBatchSize` (default 1000) with `413`; the SSE change stream is a bounded `DropOldest` channel; admin writes cap variants (50), rules (200), conditions (50), and regex length (1000).
- **Emergency bypass via the transparent gate is now audited and webhooked** (#239; closes #235) — it published no domain event before. **`change.proposed` is now actually emitted** (#233; closes #222).
- **Regex evaluation** (#197; closes #194): `Matches` prefers the linear-time `NonBacktracking` engine (immune to catastrophic backtracking) with a compiled-pattern cache, falling back to a 50 ms-bounded backtracking engine only for constructs it rejects.
- **Boot-time warning when the static admin key outlives real admins** (#244; closes #209).
- **Orphaned dashboard-auth extension point removed** (#200; closes #191) — `IFeatlyDashboardAuthorizationFilter` & co. were never wired; a Hangfire-style loopback gate, if wanted, should be built fresh as its own issue.
- Dependency pins: `SQLitePCLRaw.lib.e_sqlite3` 3.50.3 (GHSA-2m69-gcr7-jv3q, #145); the docs-site npm tree cleared of all open advisories.

### Changed

- The nine duplicated `ResolveEnvironmentAsync` copies became one `EnvironmentResolver` (#231; closes #220); the shared `EfAuditStore` / `EfWebhookStore` / `EfWebhookDeliveryStore` / `EfPendingChangeStore` / `EfMigrationRunner` bases dedupe the relational providers (ADR-0026's linked-file pattern).
- **ADR-0035** (#311; closes #224): the flag/config/segment write endpoints' structural twinning is accepted over a generic `EntityWriteFlow` — readability over the duplication metric; the ADR documents the Sonar-gate trap for future editors.
- Sweeps of the SonarCloud C# code-smell backlog (#312; progress on #182).

## [0.1.0-preview.1] - 2026-05-29

The first public preview. Ships **M12** end-to-end — the polish, tooling, third deployment sample, and documentation the project needs for a real release — on top of everything from M1–M11 (feature flags, dynamic configs, segments + the full targeting engine, experiments, custom RBAC, approval workflows, webhooks + audit, and the OpenFeature provider). New in this release: the `Featly.Cli` global tool (offline `db` schema commands; online `apikey`/`bootstrap-admin`/`env`/`export`/`import`), user-bound API keys that authenticate over Bearer and attribute actions to a real person (closing the approval-workflow limitation), a guarded first-admin bootstrap endpoint, config export/import, the standalone `Centralized.Sample`, and the full docs set (getting-started, configuration, deployment, performance, a security audit, and a complete set of ADRs). 336 tests passing. The public API is still pre-1.0 and may change before `v0.1.0` stable.

### Added

- **M12 PR 12E — documentation, ADRs, performance baseline, security audit (closes M12).** Completes the docs the first release needs: `docs/GETTING_STARTED.md` (install → first flag → local evaluation), `docs/CONFIGURATION.md` (every `Featly:*` setting, the three-layer precedence, environment variables, the CLI), and `docs/DEPLOYMENT.md` (the three deployment patterns + a production checklist + the CLI schema lifecycle). Every accepted architectural decision in ARCHITECTURE.md §22 now has a filled-in ADR — ADR-0001 through ADR-0020 plus two new ones for the M12 decisions: [ADR-0022](docs/adr/0022-cli-hybrid-online-offline.md) (the hybrid CLI) and [ADR-0023](docs/adr/0023-user-bound-api-keys.md) (user-bound API keys) — and the §22 table links them all. `docs/PERFORMANCE.md` gains a refreshed v0.1.0 baseline (boolean fast path ~37 ns, deepest realistic targeting path ~734 ns — well under the 10 μs p99 target; no regression since M3B). New `docs/SECURITY_AUDIT.md` reviews Argon2id key hashing, HMAC-SHA256 webhook signing, the cookie/CSRF posture, secret handling, the auth/authz boundaries, the guarded bootstrap endpoint, and export/import — with follow-ups recorded in `docs/DEFERRED.md`. **M12 is complete.** Docs-only; no code or API change.
- **M12 PR 12D — config export/import + `Centralized.Sample` (the third deployment pattern).** New `GET /api/admin/export` (`FlagRead`) returns a portable `FeatlyExportBundle` of an environment's flag + config + segment **definitions** (operational state — users, keys, webhooks, audit — is intentionally out of scope); `POST /api/admin/import` (`FlagCreate`) upserts a bundle into a target environment by key (matching keys overwritten in place, fresh ids assigned otherwise so importing into a different environment never collides), emitting a `configuration.imported` audit event. The CLI gains `featly export [--environment <e>] [--output <file>]` (writes the bundle, or stdout) and `featly import <file> [--environment <e>]`. New `samples/Centralized.Sample`: a standalone Featly server (server + dashboard + SQLite, **no SDK in-process**) on port 5085 that application processes point their SDK at over HTTP — completing the three documented deployment patterns (embedded = `SelfHosted.Sample`, consumer = `WebApi.Sample`, centralized = this). 5 new tests (export auth gating, export→import round-trip, import-creates-from-bundle, CLI export verbatim + import counts). Validated end-to-end against a live `Centralized.Sample`: seed a flag → `featly export` → `featly import`. 336 tests passing total. No breaking change.
- **M12 PR 12C — `featly` CLI online commands (`apikey generate`, `bootstrap-admin`, `env lock`/`unlock`).** The online half of the hybrid CLI: these talk to a running server's admin API over HTTP, reusing its permission checks, audit log, and webhook backbone. `featly apikey generate --name <n> [--user <id>] [--scope <s>] [--environment <e>]` mints a key (`POST /api/admin/apikeys`) and prints the plaintext token once; `featly bootstrap-admin --identifier <id>` provisions the first admin on a fresh server (`POST /api/admin/bootstrap`, no credential needed — it self-guards); `featly env lock|unlock <key>` toggles an environment's ReadOnly freeze. The server URL resolves from `--server-url`/`-s`, then `FEATLY_SERVER_URL`, then `http://localhost:5080`; the admin key from `--api-key`/`-k`, then `FEATLY_API_KEY` (bootstrap needs none). Failures surface the server's error message and a non-zero exit code. New `AdminApiClient` (testable against a stub handler) + `ServerConnection` resolver. 9 new tests (request shaping for each endpoint + response parsing + server-error surfacing + connection resolution). Validated end-to-end against a live `SelfHosted.Sample`: bootstrap-admin → mint a user-bound key → env lock/unlock → second bootstrap rejected with `409`. 331 tests passing total. No breaking change.
- **M12 PR 12B — user-bound API keys + mint/bootstrap endpoints + Bearer auth for persisted keys.** Closes the M8 limitation where an API key was an anonymous `api-key:AdminWrite` pseudo-identity that could not be a real approver. `ApiKey` gains an optional `UserId` binding (migration `AddApiKeyUserBinding`); when set, a request authenticated with that key resolves to the bound user's identifier, so RBAC, the audit log, and the approval workflow all attribute the action to a real person. The Bearer admin/SDK handler now validates persisted `ApiKey` rows (prefix lookup + Argon2id verify, filtered to the scheme's scope) in addition to the static appsettings key — so a minted key actually authenticates over `Authorization: Bearer` (the DB lookup runs only when a bearer token is present and the static key didn't match, so cookie and bootstrap-key requests pay no Argon2 cost). New `POST /api/admin/apikeys` (`ApiKeyCreate`) mints a key — optionally bound to a user (auto-created on first sight) — and returns the plaintext token exactly once; `GET /api/admin/apikeys` (`ApiKeyRead`) lists metadata only (never the hash or token); `POST /api/admin/apikeys/{id}/revoke` (`ApiKeyRevoke`) soft-revokes. New guarded, unauthenticated `POST /api/admin/bootstrap` provisions the first admin when the instance has zero users — it creates the user, grants it the system `admin` role, and mints an admin key bound to it (returned once); every later call returns `409`. `apikey.created` / `apikey.revoked` / `admin.bootstrapped` domain events feed the audit log + webhooks. 7 new tests (mint auth gating; minted key authenticates over Bearer; a bound key acts as its user, not a blanket admin; revoke disables auth; list hides the secret; bootstrap provisions once + attributes actions to the real user + 409 on repeat; SQLite `UserId` round-trip). 322 tests passing total. No breaking change.
- **M12 PR 12A — `featly` CLI scaffold + offline `db` commands.** First slice of M12 (PLAN.md M12; ARCHITECTURE.md §19). The `Featly.Cli` global tool (`featly`) gains a real command tree built on `System.CommandLine`, starting with the `db` group that operates the SQLite schema **offline** — directly against the database file, with no running server (the server cannot start before its schema exists). New public `SqliteMigrationRunner` facade in `Featly.Storage.Sqlite` exposes `MigrateAsync` / `GetStatusAsync` / `RollbackAsync(target)` / `DropAsync` while keeping `FeatlyDbContext` `internal` — tooling never references an EF Core type. Commands: `featly db migrate` (apply pending migrations; idempotent), `db status` (applied vs pending), `db rollback <target>` (revert to a migration, or `0` for the empty schema; confirmation-gated), `db drop` (delete the database; confirmation-gated). Destructive commands prompt unless `--yes`/`-y`; the connection string resolves from `--connection-string`/`-c`, then the `FEATLY_SQLITE` environment variable, then the `Data Source=featly.db` default (a bare path is wrapped as a `Data Source=`). A single error boundary turns any failure into a friendly one-line message and a non-zero exit code. New `tests/Featly.Cli.Tests` (10 tests: end-to-end migrate/status/rollback/drop against a throwaway database + connection-string resolution). The remaining CLI commands — `apikey generate`, `bootstrap-admin`, `env lock`/`unlock`, `export`/`import` — go through the server's HTTP API and land in 12B/12C. 315 tests passing total. No breaking change.

## [0.0.2-preview.1] - 2026-05-26

First substantive preview. v0.0.1 reserved the package names with empty placeholders; v0.0.2-preview.1 ships the full Featly stack through M4 (multi-variant flag evaluation engine + dynamic configs + segments + targeting rules end-to-end).

### Changed

- **Extract `InProcessChangeNotifier` into `Featly.Storage.Abstractions`.** The InMemory and SQLite providers previously each shipped a near-identical `IChangeNotifier` implementation (concurrent dictionary of handlers, subscriber-isolation `catch`, dispose-once subscription). Replaced by a single public `Featly.Storage.InProcessChangeNotifier` that both providers (and any future single-instance provider) consume. `InMemoryChangeNotifier` and `SqliteChangeNotifier` are gone. No public-API change for the storage facade: `IChangeNotifier`-typed consumers see the same contract.
- **Persist `DateTimeOffset` audit timestamps as 64-bit UTC ticks in SQLite.** New `DateTimeOffsetTicksConverter` value converter, applied to `CreatedAt` / `UpdatedAt` on Project, Environment, Flag, Segment, and Config. `MAX` and `ORDER BY` now run server-side instead of pulling N timestamps and aggregating client-side; `GetMostRecentUpdateAsync` on `SqliteFlagStore` / `SqliteSegmentStore` / `SqliteConfigStore` uses `.MaxAsync()`. EF migration `ConvertTimestampsToUtcTicks` alters the columns from `TEXT` to `INTEGER`. **Breaking for any dev database that holds existing rows**: SQLite's implicit `CAST(text AS INTEGER)` produces garbage values for the migrated rows (each ISO-8601 string collapses to the leading year integer). Delete `featly.db` and let the bootstrap recreate it. Production has no real users at v0.0.x, so the breaking change is intentionally tolerated.
